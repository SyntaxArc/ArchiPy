# 5.25.0 — 2026-11-01

[5.24.0 →](5.24.0.md) | [↑ 5.x series](index.md)

## Added

### Adapters - Kafka

- **SASL and SSL Settings** - Each setting applies on its own: `security.protocol` is always set, SASL settings apply for `SASL_*` protocols and SSL settings for `SSL` and `SASL_SSL`. mTLS-only, `SASL_PLAINTEXT`, GSSAPI, OAUTHBEARER and system CA stores work now.
    - `KafkaConfig` requires a SASL mechanism for SASL protocols, and a username and password only for `PLAIN` and `SCRAM`
- **Client Options** - `SOCKET_TIMEOUT_MS`, `RECONNECT_BACKOFF_MAX_MS`, `RETRY_BACKOFF_MS`, `MESSAGE_TIMEOUT_MS`, `GROUP_INSTANCE_ID` and `ENABLE_AUTO_OFFSET_STORE` are optional settings; unset keeps the librdkafka default.

### Adapters - Redis

- **TLS and ACL Login** - `USERNAME`, `SSL`, `SSL_CA_CERTS`, `SSL_CERTFILE`, `SSL_KEYFILE` and `SSL_CHECK_HOSTNAME` work for standalone, cluster and sentinel clients, sync and async.
- **Retry and Connection Options** - `RETRY_ATTEMPTS`, `RETRY_BACKOFF_BASE`, `RETRY_BACKOFF_CAP`, `RETRY_ON_TIMEOUT`, `SOCKET_KEEPALIVE`, `CLIENT_NAME` and `SENTINEL_USERNAME`; unset keeps the redis-py defaults.

### Adapters - ScyllaDB

- **TLS** - `TLS_ENABLED`, `TLS_CA_FILE`, `TLS_CERT_FILE`, `TLS_KEY_FILE`, `TLS_VERIFY_MODE` and `TLS_CHECK_HOSTNAME` build the `ssl_context` of the sync and async clusters.
- **Resilience Options** - Idle heartbeat interval and timeout, control connection timeout, reconnection policy, serial consistency level and speculative execution apply to the cluster and the default execution profile.

### Adapters - Email

- **TLS Modes** - `TLS_MODE` is `none`, `starttls` (required: a failed upgrade raises instead of sending in clear text) or `implicit` (port 465), next to `TLS_CA_FILE`, `TLS_VERIFY`, `LOCAL_HOSTNAME`, `SOURCE_ADDRESS` and `SOURCE_PORT`.
    - A half-set username and password pair is rejected outside the `auto` mode

### Adapters - PostgreSQL and MySQL

- **TLS** - PostgreSQL `SSL_MODE`, `SSL_ROOT_CERT`, `SSL_CERT` and `SSL_KEY`; MySQL `SSL_MODE`, `SSL_CA`, `SSL_CERT` and `SSL_KEY`. Sync and async.
- **Timeouts and Options** - MySQL `CONNECT_TIMEOUT`, `READ_TIMEOUT`, `WRITE_TIMEOUT` (pymysql only), `STATEMENT_TIMEOUT_MS` and `LOCK_WAIT_TIMEOUT_SECONDS`; PostgreSQL `STATEMENT_TIMEOUT_MS`, `LOCK_TIMEOUT_MS`, `APPLICATION_NAME`, `PREPARE_THRESHOLD` and `DISABLE_PREPARED_STATEMENTS` for pgbouncer in transaction mode.

### Adapters - SQLite

- **Busy Timeout** - `TIMEOUT` sets the busy timeout and `CHECK_SAME_THREAD` the sync driver option.

### Adapters - Elasticsearch

- **Client Options** - `BEARER_AUTH`, `CLOUD_ID`, `SSL_VERSION`, `SSL_CONTEXT`, `OPAQUE_ID` and `HEADERS` are passed to the sync and async clients when set. Bearer auth is rejected together with an API key or basic auth, and `CLOUD_ID` replaces `HOSTS`.

### Adapters - Keycloak

- **Connection Settings** - `VERIFY_SSL` accepts a CA bundle path and `TIMEOUT` a float. New `CLIENT_CERT_FILE` and `CLIENT_KEY_FILE` (mTLS), `MAX_RETRIES`, `POOL_MAXSIZE`, `PROXIES` and `CUSTOM_HEADERS` reach every python-keycloak client.
    - python-keycloak has no connect and read timeout split, and its async admin and UMA clients take no proxies

### Adapters - MinIO

- **Client Options** - `CLIENT_CERT`, `CLIENT_KEY`, `PROXIES`, `PROXIES_CONFIG`, `TCP_KEEPALIVE`, `USER_AGENT_EXTRA` and `PROFILE_NAME` reach the botocore client; a profile with `role_arn` covers STS assume-role.

### Configs - Uvicorn

- **UVICORN Section** - The Uvicorn server settings live in the new `UVICORN` section, with `SSL_KEYFILE`, `SSL_CERTFILE` and `SSL_CA_CERTS` for TLS (the key and certificate must come together). `AppUtils.uvicorn_config()` builds the `uvicorn.run` arguments from it and drops unset optional settings.

### Configs - gRPC

- **TLS and mTLS** - `TLS_*` and `STUB_TLS_*` settings, with `AppUtils.add_grpc_port` for secure server ports and `AppUtils.create_grpc_channel` for secure channels. Off by default.
- **Compression and Shutdown** - `SERVER_COMPRESSION`, `STUB_COMPRESSION` and `SHUTDOWN_GRACE_SECONDS`, with `AppUtils.stop_grpc_app`. Server option values may be strings as well as integers.

## Changed

### Adapters - Kafka

- **List Topics Timeout** - **Behavior:** `list_topics()` without a timeout waits `LIST_TOPICS_TIMEOUT_MS` (5 seconds) instead of 1 second.

### Adapters - Elasticsearch

- **Sniff Delay** - **Behavior:** with `SNIFF_BEFORE_REQUESTS` on, the delay between sniffs is `MIN_DELAY_BETWEEN_SNIFFING` (60 seconds by default) instead of the library's 10 seconds.

### Adapters - Email

- **TLS Mode Default** - The default `TLS_MODE` `auto` keeps the old opportunistic STARTTLS and is deprecated; set `starttls`, `implicit` or `none` explicitly.

### Configs - FastAPI

- **Uvicorn Settings Moved** - **Deprecated:** the uvicorn fields of `FASTAPI` (`ACCESS_LOG`, `BACKLOG`, `DATE_HEADER`, `FORWARDED_ALLOW_IPS`, `LIMIT_CONCURRENCY`, `LIMIT_MAX_REQUESTS`, `PROXY_HEADERS`, `RELOAD`, `SERVER_HEADER`, `TIMEOUT_GRACEFUL_SHUTDOWN`, `TIMEOUT_KEEP_ALIVE`, `WORKERS_COUNT` and the four `WS_*`) move to `UVICORN`. They still apply when the matching `UVICORN` field is unset.
    - Building `FastAPIConfig` with one, or reading one, emits a `DeprecationWarning`; the JSON schema marks it deprecated
    - Removed in 6.0.0; see the deprecations page

### Configs - ScyllaDB

- **Pool Fields Deprecated** - **Deprecated:** `MAX_CONNECTIONS_PER_HOST`, `MIN_CONNECTIONS_PER_HOST`, `CORE_CONNECTIONS_PER_HOST` and `MAX_REQUESTS_PER_CONNECTION` are marked with pydantic `deprecated`, so reading one warns. They never had an effect and are removed in 6.0.0.

## Fixed

### Adapters - Kafka

- **Dropped Settings** - `CLIENT_ID`, `CONNECTIONS_MAX_IDLE_MS` and `LIST_TOPICS_TIMEOUT_MS` are applied; they were never read.
- **Silent Plaintext** - A config with a SASL or SSL protocol and no username, password and CA together no longer falls back to plaintext without notice.

### Adapters - Elasticsearch

- **Dropped Settings** - `NODE_SELECTOR_CLASS`, `DEAD_NODE_BACKOFF_FACTOR`, `MIN_DELAY_BETWEEN_SNIFFING` and `IGNORE_STATUS` are applied to the sync and async clients; they were never passed on.

### Adapters - Email

- **STARTTLS Downgrade** - With `TLS_MODE` set to `starttls`, a failed upgrade raises instead of sending the login in clear text.

## Tests

### Tests - Configuration

- **New Scenarios** - Redis ACL login on a container, Postgres and MySQL TLS and timeouts on real containers, SQLite busy timeout, gRPC TLS and mTLS against real servers, ScyllaDB TLS contexts built from generated certificates, Kafka option outlines, Elasticsearch option wiring, and the deprecated field warnings.
    - Redis TLS is tested at the client-settings level because there is no TLS server container, and Mailpit has no SMTPS listener, so email implicit TLS runs against a local TLS stub

# 5.24.0 — 2026-11-01

[5.23.0 →](5.23.0.md) | [↑ 5.x series](index.md)

## Added

### Helpers - OpenTelemetry

- **Per-Signal OTLP Headers** - `TRACES_HEADERS`, `METRICS_HEADERS` and `LOGS_HEADERS` set the OTLP headers of one signal, so traces and logs can send a `Bearer` token while metrics send `Basic` credentials with `X-Scope-OrgID` and `Tenant-ID`.
    - A per-signal value replaces `OTLP_HEADERS` for that signal and is not merged with it
    - `USE_STANDARD_ENV` reads `OTEL_EXPORTER_OTLP_TRACES_HEADERS`, `OTEL_EXPORTER_OTLP_METRICS_HEADERS` and `OTEL_EXPORTER_OTLP_LOGS_HEADERS`; the OpenTelemetry parser lowercases header names
    - The Temporal SDK metrics runtime uses `METRICS_HEADERS`
- **OTLP TLS and mTLS** - `CERTIFICATE`, `CLIENT_CERTIFICATE`, `CLIENT_KEY` and `INSECURE` configure TLS for the OTLP exporters, shared as `OTLP_*` and per signal as `TRACES_*`, `METRICS_*` and `LOGS_*`.
    - gRPC exporters get channel credentials built from the PEM files; HTTP exporters get the file paths and follow the URL scheme
    - A client certificate without a client key, or the reverse, is rejected
    - `USE_STANDARD_ENV` reads the matching `OTEL_EXPORTER_OTLP_*` variables
- **Span and Attribute Limits** - `ATTRIBUTE_COUNT_LIMIT`, `ATTRIBUTE_VALUE_LENGTH_LIMIT`, `SPAN_ATTRIBUTE_COUNT_LIMIT`, `SPAN_ATTRIBUTE_VALUE_LENGTH_LIMIT`, `SPAN_EVENT_COUNT_LIMIT` and `SPAN_LINK_COUNT_LIMIT` cap what a span keeps, and reach the tracer provider, including the replay-safe Temporal one, as `SpanLimits`. Unset keeps the SDK defaults; `USE_STANDARD_ENV` reads the matching `OTEL_*_LIMIT` variables.

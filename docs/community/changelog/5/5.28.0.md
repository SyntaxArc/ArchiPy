# 5.28.0 — 2026-11-02

[← 5.27.0](5.27.0.md) | [↑ 5.x series](index.md)

## Changed

### Adapters - SQLAlchemy

- **Logic Exceptions** - The atomic decorator no longer converts business or logic exceptions to `InternalError`.
    - Only `SQLAlchemyError` failures are mapped to `Database*Error`; every other exception keeps its type, message and traceback
    - `DatabaseTransactionError` is reserved for genuine transaction failures
- **Nested Failures** - A default nested failure still rolls back the whole transaction, but the outer block now re-raises the original exception instead of `DatabaseTransactionError`.
    - The first nested failure is preserved and re-raised at the outer boundary
    - A failure to roll back is logged and does not hide the original exception
    - `savepoint=True` keeps its isolation behavior and re-raises the inner exception to its caller

## Tests

### Tests - SQLAlchemy

- **Error Propagation** - Nested, mixed-mode and failed-rollback scenarios assert the original `ValueError`; SQLAlchemy failures still map to the existing database errors.
